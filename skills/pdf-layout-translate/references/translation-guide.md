# 翻译规范

`todo` 输出的每一行是一个待译段落。译文写成一个 JSON 对象（UTF-8），键是 `k`，值是译文：

```json
{"3": "参考以下幻灯片安装 PostgreSQL。", "4": "{v1}选择安装目录，然后点击“下一步”(Next)", "i12": "取消"}
```

## 正文段落（编号是数字）

- **占位符必须原样保留**：`{v1}`、`{v2}`… 代表公式、符号、项目符号或个别标点。顺序可以按中文语序调整，但每个占位符都要出现，也不能新增。
  - `ph` 字段给出每个占位符代表的原字符，帮助理解句子。
  - 只代表标点或数字的占位符（如 `_`、`[`、`=`）在成品里会按普通文字写回。
  - `<style id='1'>…</style>` 是原文的局部样式，要包住对应的词。不是所有粗体都会带这个标签。
- **译文与原文相同表示保留原文**：代码、命令、SQL、文件名、路径、网址、邮箱、人名、产品名、变量名、参考文献条目都这样处理。代码段只要整体照抄原文即可。
- 行首的编号和项目符号（`a.`、`(1)`、`●`、行首的 `{v1}`）留在行首。
- 一句话被分进两个段落时（前一段在句中断开），分别翻译两部分，让两段连起来读通顺。标点归前一段，后一段不要以句号开头。
- 不能用 `\n` 换行，会被忽略；需要分行的内容用分号或顿号隔开，让它作为一段话读得通。
- 只翻译，不加解释或译注。用中文标点。中文和英文、数字之间的空格会自动去掉，不必处理。
- 同一份资料里的术语要前后一致。同一门课沿用 `--carry-from` 带来的以前译文。
- 正文提到截图里的按钮或菜单时，写成截图翻译后的文字并附原文，例如 点击“下一步”(Next)。
- 偶尔会出现页面上看不到的文字（隐藏或页外的文本框），照常翻译即可，不会显示出来。

## 图片里的文字（编号以 i 开头）

这些文字来自 OCR，可能有识别错误。

- **翻译**：标题、说明句、按钮和菜单文字、表头、程序输出的提示语。例如 psql 的 `(1개 행)` 译为 `(1 行)`。要翻译的内容识别错了时，打开 `image` 给出的图片，按图上的实际内容翻译，例如 OCR 读成 `"hetp"`，图上其实是 `"help"`。
- **译文与原文相同表示不动这段**：代码、SQL、命令行提示符、路径、表格里的数据、产品名、书封、标志、`Label: 值` 这类设置列表中的值。表头是字段名或标识符时（如 `dept_name`、`building`）也不动。这类内容即使 OCR 认错了，也照抄 `src`，不要写成改正后的文字，否则会被重画。
- 一行只识别出一部分（图上还有字没进 `src`）时保持原样，免得半句中文半句原文。一张图大部分认不出来时，整张图都保持原样。
- 行首的项目符号（`·`、`•`、`○`）出现在 `src` 里时，译文开头也照样保留，不要另加符号。
- 空字符串 `""` 只擦除不写；`\n` 强制换行（例如标题和副标题被合进同一段时）。
- 扫描件没有文字层，整页内容都会作为图片文字出现在 `todo` 里，按正文的规则翻译即可。
- 相同的文字（每个对话框里的“下一步”“取消”）只出现一次，译一次就会用到所有位置。
- 译文尽量不比原文长，过长时会自动缩小字号。
